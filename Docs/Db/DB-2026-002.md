# DB-2026-002: Sistem ayarları ve ayar değişiklik geçmişi, üç ayar satırı seed

Durum: UYGULANDI
Faz: 1   Talep eden: backend-engineer   Tarih: 2026-11-14   Sınıf: Eklemeli

## Talep (backend-engineer)

Neden: Faz 1 ayar servisi (PhasePlan Faz 1 kalem 2 ve 3): oturum süresi, PIN uzunluğu, PIN deneme sınırı her istekte veritabanından okunur (K-47, PL-17, PL-18, PL-24, PL-25). Değişiklik geçmişi tablosu Faz 9'daki ayar ekranı için bu fazda gelir (tablo sonradan değiştirilmesin, PL-02). Bu talep `DB-2026-001` (Users) tablosuna bağlıdır; aynı migration ya da ondan sonraki migration olabilir.

İstenen:

Ortak kurallar `DB-2026-001` ile aynıdır (PascalCase, UTC `DateTime`, ad alanları). Entity'ler `SystemSetting`, `SettingChange`; `DbSet<SystemSetting> SystemSettings`, `DbSet<SettingChange> SettingChanges`.

`SystemSettings`: ayar başına bir satır.

| Kolon | Tip | Kural |
|---|---|---|
| Id | int PK | |
| Key | metin, en çok 64 | Zorunlu, benzersiz index |
| Value | int | Zorunlu; `Value > 0` CHECK (sıfır ve negatif veritabanında reddedilir, K12a) |
| Unit | metin, en çok 16 | Zorunlu (dakika, hane, deneme, MB) |

`SettingChanges`: yalnız eklenir.

| Kolon | Tip | Kural |
|---|---|---|
| Id | int PK | |
| SettingId | int FK SystemSettings.Id | Zorunlu, OnDelete Restrict |
| OldValue | int | Zorunlu |
| NewValue | int | Zorunlu |
| ChangedByUserId | int FK Users.Id | Zorunlu, OnDelete Restrict |
| ChangedAtUtc | DateTime | Zorunlu |

Index: `SettingChanges(SettingId, ChangedAtUtc)` (ayar başına geçmiş listesi, Faz 9), `SettingChanges(ChangedByUserId)` (FK). `SystemSettings(Key)` benzersiz (her istekte anahtarla okuma).

Seed: tam üç satır, değişiklik geçmişi boş. Anahtarlar kodda `Services/SettingKeys` sabitleriyle okunur; metinler birebir aşağıdaki gibi olmalıdır:

| Key | Value | Unit |
|---|---|---|
| `SessionMinutes` | 30 | dakika |
| `PinLength` | 4 | hane |
| `PinAttemptLimit` | 5 | deneme |

Başka ayar satırı (medya boyutu, azami kilit süresi) yazılmaz; Faz 3'te seed ekleme olarak gelir (PL-25). Boş ya da yer tutucu değerli satır yok.

Backend sözleşmesi: `SystemSetting.Key, Value, Unit`; `SettingChange.SettingId, OldValue, NewValue, ChangedByUserId, ChangedAtUtc`. Faz 1'de backend yalnız `SystemSettings` okur.

## Tasarım ve sonuç (dbadmin)
Tablolar/ilişkiler: `SystemSettings` ve `SettingChanges` talepteki kolonlarla kuruldu. `SettingChanges.SettingId` -> `SystemSettings.Id` ve `SettingChanges.ChangedByUserId` -> `Users.Id`, ikisi de Restrict. CHECK `CK_SystemSettings_Value`: `Value > 0`. Navigation: `SettingChange.Setting`, `SettingChange.ChangedByUser` (ters yönde koleksiyon yok).
Index'ler: `IX_SystemSettings_Key` benzersiz; `IX_SettingChanges_SettingId_ChangedAtUtc`; `IX_SettingChanges_ChangedByUserId`.
Migration: `AddUsersRolesAndSettings` (DB-2026-001 ile aynı, Users tablosundan sonra sıralı). `Up()` içinde Drop/Alter yok.
Seed etkisi: `SystemSettings` 3 satır: `SessionMinutes` 30 dakika, `PinLength` 4 hane, `PinAttemptLimit` 5 deneme (`Data/Seed/SettingSeed.cs`, anahtarlar `SettingKeys` sabitleri). `SettingChanges` boş.
Onay (yalnız ALTER): gerekmez (Eklemeli)
Doğrulama: `dotnet ef database update` uygulandı; `has-pending-model-changes` temiz; `dotnet build` 0 uyarı; SystemSettings 3 satır, SettingChanges 0.
Backend'in bilmesi gerekenler: Ortak bilgiler DB-2026-001 kaydında (DbContext `Vaka.Web.Data.VakaDbContext`, `ConnectionStrings:Default` = `Data Source=App_Data/vaka.db`, fabrika `VakaDbContextFactory`). Entity alan adları talep sözleşmesiyle aynı. Faz 3 ayar satırları seed ekleme olarak yeni migration'la gelir (`Id` 4 ve sonrası).
