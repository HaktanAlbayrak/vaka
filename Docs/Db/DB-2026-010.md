# DB-2026-010: Giriş deneme sayacı ve süreli kilit (Users kolonları, LoginLockMinutes)

Durum: DOĞRULANDI
Faz: 6F   Talep eden: backend-engineer   Tarih: 2026-11-17   Sınıf: ALTER (mevcut tabloya kolon ekleme) ve Eklemeli (ayar seed'i)

> ALTER sınıfı: `Users` mevcut tablodur. Kullanıcı bu seçeneği O-10'da seçti (ayrı giriş sayacı), `<GirişKilitSüresi>` 15 dakikayı O-11'de verdi.
> DbProtocol §2 gereği dbadmin uygulamadan durur; koordinatör kullanıcıdan yeniden onay alır ve onay "Onay" satırına işlenir.

## Talep (backend-engineer)

Neden: Faz 6F (O-10, O-11). Parola ve PIN girişindeki hatalı denemeler işlem PIN sayacından (`PinFailedCount`, `PinLockedAtUtc`) bağımsız bir giriş sayacında tutulur; sınıra ulaşınca giriş süreli kapanır. Giriş ekranından kimsenin işlem PIN'i kilitlenemez (PL-94). Kaynaklar: PhasePlan Faz 6F "Şema" bölümü, kalem 1; K3, K4, K5, K10.

Sınıf gerekçesi: `Users` tablosuna iki kolon eklenir. SQLite'ta `ADD COLUMN` tabloyu yeniden kurmaz (`NOT NULL` kolon için `DEFAULT` verilir). Başka tabloya, kısıta, index'e ya da tetikleyiciye dokunulmaz; DROP yok.

İstenen:

| Tablo | Kolon | Tip | Kural |
|---|---|---|---|
| `Users` | `LoginFailedCount` | INTEGER NOT NULL | `DEFAULT 0`; entity `User.LoginFailedCount` (`int`) |
| `Users` | `LoginLockedUntilUtc` | TEXT NULL | UTC an; entity `User.LoginLockedUntilUtc` (`DateTime?`); boşsa kilit yok |

- Mevcut satırlar varsayılanla `0` ve `NULL` alır. Veri `UPDATE` yok, index yok (sorgu hep kullanıcı satırı üzerinden, sicil no ile bulunan tek satır).
- `Down` yalnız geri alma.
- Ayar tablosuna (`SystemSettings`) `LoginLockMinutes` satırı: değer `15`, birim dakika (`<GirişKilitSüresi>`, kullanıcı O-11). Mevcut ayar satırlarının biçimi (anahtar, değer, açıklama, alt ve üst sınır alanları varsa) `PinLockMinutes` benzeri satırlarla aynı kurulur; idempotent seed, mevcut veriyi ezmez. Sistem ayarları ekranı kapsam dışı (O-14); değer yalnız seed ya da veritabanından değişir. Backend sabiti `SettingKeys.LoginLockMinutes = "LoginLockMinutes"`.
- Sınır değeri için yeni ayar yok; giriş de mevcut `<PinDenemeSınırı>` (5) değerini kullanır.

Beklenen sorgular: `Users` satırı sicil no ile okunur; başarısız denemede `LoginFailedCount` artar ve sınırda `LoginLockedUntilUtc` yazılır; başarılı girişte ve kilit açmada `LoginFailedCount = 0`, `LoginLockedUntilUtc = NULL`.

Beklenen migration: yalnız iki `AddColumn` ve `LoginLockMinutes` ayar seed'i (K10). Başka değişiklik çıkarsa dbadmin durur ve bildirir.

## Tasarım ve sonuç (dbadmin)
Tablolar/ilişkiler: `Users` tablosuna iki kolon: `LoginFailedCount` INTEGER NOT NULL DEFAULT 0 (`HasDefaultValue(0)`), `LoginLockedUntilUtc` TEXT NULL. Yeni ilişki yok. `CK_Users_PinFailedCount` ve diğer kısıtlar yerinde.
Index'ler: yok (talep gereği).
Migration: `20261116214722_AddLoginLockToUsers`. Üretilen SQL (`dotnet ef migrations script`): `ALTER TABLE "Users" ADD "LoginFailedCount" INTEGER NOT NULL DEFAULT 0;`, `ALTER TABLE "Users" ADD "LoginLockedUntilUtc" TEXT NULL;`, `INSERT INTO "SystemSettings" ("Id","Key","Unit","Value") VALUES (7,'LoginLockMinutes','dakika',15);`. Tablo yeniden kurma yok. EF'in ürettiği `UpdateData(Users, Id=1, LoginLockedUntilUtc = null)` (HasData eşleme artığı, yeni kolon zaten NULL, etkisiz) migration'dan çıkarıldı; model farkı kalmadı (`has-pending-model-changes`: temiz). `Drop*` yalnız `Down()` içinde. Snapshot farkı salt ekleme (16 satır eklendi, 0 silindi).
Seed etkisi: `SettingSeed` içine Id 7, `LoginLockMinutes`, 15, "dakika" eklendi (mevcut 6 satır ve biçim aynı, HasData deseni; `SettingKeys.LoginLockMinutes` sabiti gelince backend aşama 2'de seed'deki sabit metin sabitle değiştirilebilir, değer aynı kalmalı). Mevcut satırlar ezilmez. Migration bir kez çalıştığı için tekrar uygulamada çift satır oluşmaz.
