# DB-2026-003: CK_UserRoles_Role ifadesi Roles sabitlerinden kurulsun

Durum: UYGULANDI
Faz: 1   Talep eden: backend-engineer   Tarih: 2026-11-14   Sınıf: Eklemeli

## Talep (backend-engineer)

Neden: Faz 1 teslim bulgusu B5 (PL-30). Rol adları `Authorization/Roles.cs` dışında metin olarak geçmez (TK9); `Data/Configurations/UserRoleConfiguration.cs:12-14` içindeki CHECK ifadesi `'Operator', 'Manager', 'Auditor', 'SuperAdmin'` metnini elle taşıyor.

İstenen: `UserRoleConfiguration` içinde `CK_UserRoles_Role` ifadesi `Roles` sabitlerinden (`Roles.Operator`, `Roles.Manager`, `Roles.Auditor`, `Roles.SuperAdmin`) kurulsun. Üretilen SQL birebir aynı kalmalı: `"Role" IN ('Operator', 'Manager', 'Auditor', 'SuperAdmin')`. Şema değişmez, yeni migration oluşmaz; mevcut migration ve snapshot dosyalarındaki metin üretilmiş geçmiş kayıt olarak istisnadır, elle değiştirilmez.

Kabul: `dotnet ef migrations has-pending-model-changes` temiz. Model farkı çıkarsa dbadmin durur, migration üretmez, B5 Faz 2'ye ertelenir. Sınıf Eklemeli sayıldı çünkü veritabanına hiçbir işlem uygulanmıyor; fark çıkarsa talep ALTER sınıfına döner ve kullanıcı onayı ister.

## Tasarım ve sonuç (dbadmin)
Tablolar/ilişkiler: değişmedi. Yalnız `UserRoleConfiguration` içindeki CHECK ifadesi `$"\"Role\" IN ('{Roles.Operator}', '{Roles.Manager}', '{Roles.Auditor}', '{Roles.SuperAdmin}')"` olarak kuruldu (`using Vaka.Web.Authorization` eklendi). Üretilen SQL aynı.
Index'ler: değişmedi.
Migration: yok. Mevcut migration ve snapshot dosyalarına dokunulmadı.
Seed etkisi: yok.
Onay (yalnız ALTER): gerekmedi, model farkı çıkmadı.
Doğrulama: `dotnet ef migrations has-pending-model-changes --configuration Release --no-build` (Release derlemesi, çünkü Debug `bin` başka süreç tarafından kilitli) çıktısı: "No changes have been made to the model since the last migration." Veritabanına komut uygulanmadı. Sonuç: UYGULANDI, B5 kapandı.
Backend'in bilmesi gerekenler: yok. Debug `bin` kilidi sürdüğü için Debug çıktısı eski kod içerir; kilit kalkınca normal derleme yeterli.
